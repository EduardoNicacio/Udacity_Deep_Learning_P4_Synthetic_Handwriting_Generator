## 1. Elevator Pitch

**The Problem:** A CAPTCHA-style human-verification product needs a supplier of synthetic handwritten digits: given a class label 0-9, generate realistic, diverse digit images on demand, and be able to argue quantitatively which generative approach is better. The deliverable is not one model but a complete, executed comparison pipeline - a **Conditional GAN** and a **Conditional Diffusion Model (DDPM)**, both trained on MNIST, both evaluated with **FID** (realism + diversity) and with **downstream CNN accuracy** (train ONLY on synthetic digits, test on real MNIST), with a side-by-side visual comparison grid and written conclusions. The training machine is a laptop with a **4 GB** RTX 500 Ada GPU, so the UNet's 200-step reverse chain had to run on a second-by-second VRAM budget; and the notebooks' printed numbers had to match the written analysis exactly.

**The Solution:** Six `starter/` modules implemented around the starter's real call sites (`model/cgan.py`, `model/diffusion.py`, `training/train_cgan.py`, `training/train_diffusion.py`, `utils/metrics.py`, extended `utils/visualize.py`/`data_utils/dataloader.py`) plus four notebooks executed top-to-bottom headless with `jupyter nbconvert --execute`. The cGAN is the full MLP design from the brief: Generator concatenates a `nn.Embedding(10, 32)` label embedding with `z` and upsamples 132→256→512→1024→784 through BatchNorm+LeakyReLU(0.2) to a Tanh output (**1,498,448 parameters**); Discriminator broadcasts the label as an extra spatial channel so it sees `(B,2,28,28)`, flattens to 1,568 and scores through 1024-512-256-1 with Dropout(0.3) (**2,263,051 parameters**). The diffusion denoiser is the starter's `ConditionalUNet` - sinusoidal timestep embedding, label embedding fused into every ResidualBlock, down path 28→14→7 (64/128/256 channels), mid block, up path with skip connections, 1×1 conv noise head (**3,414,209 parameters**) - trained at **T=200** with a linear β schedule (1e-4 → 0.02) using the exact `x_t = √ᾱ·x_0 + √(1-ᾱ)·ε` forward process and the DDPM reverse update. Both trainings run `torch.amp.autocast` + `GradScaler`, with OOM guard-rails that halve the batch and retry once before raising.

**The Result:** The cGAN reached **FID 69.92** and a downstream CNN (trained only on its 1,000 synthetic digits) reached **89.9% accuracy on the real 10,000-image MNIST test set**; the diffusion model reached **FID 33.72** and **91.3%** - diffusion wins both head-to-head metrics, at ~200× the sampling cost (one forward pass vs. a 200-step reverse chain). An independent conditioning audit classified **88.7%** of cGAN outputs as their conditioning label with a real-data-trained CNN. Measured peak VRAM was **0.47 GB** (diffusion training at batch 64), **0.25 GB** (100-image fp32 sampling) and **0.14 GB** (cGAN training at batch 128) - zero OOMs across all runs, so the halving guard-rail never had to fire. All four notebooks executed with zero errors, and 205 checkpoint files (6.28 GB) document every epoch.

### Key Design Decisions

| Decision | Rationale |
| :--- | :--- |
| **Follow the starter's real state, then fix what was actually broken** | Plan-mode inspection showed the brief's file map was wrong (`data/dataloader.py` vs the real `data_utils/dataloader.py`; `utils/metrics.py` listed in the README but missing), that the UNet forward and the diffusion loop were **already implemented** in the starter, and that `train_cgan.py` contained a working-but-wrong loop (G trained before D; checkpoints written to a nonsense path). Working starter code was kept; broken code was rewritten; missing pieces were created. |
| **Spec architecture for the cGAN, starter architecture for the UNet** | The brief specified a concrete MLP architecture (label embedding concatenated to z; label as an extra image channel in D); it was implemented exactly, including the `256→512→1024→784` generator. The UNet was already rubric-compliant (time+label embeddings, skip connections, same-shape noise output), so only the hacky `t.shape[0]*0+128` expressions were replaced with a stored `self.time_dim`. |
| **Discriminator updated before the Generator** | The deliverable loop is D-then-G per batch (real loss + fake loss averaged → one D step; then a G forward through the fresh D, BCE vs ones → G step). Ordering D-first matches the brief and the classical minimax formulation; reusing the batch's `gen_imgs` for the G update (without `detach`) keeps one generation cost per batch instead of two. |
| **BCE evaluated in fp32 outside the autocast block** | PyTorch refuses `F.binary_cross_entropy` inside an autocast region ("unsafe to autocast"). The delivered loop keeps all forwards under `autocast`, then computes both BCE losses on `.float()`-cast predictions, keeping the scaler contract (`scale → backward → step → update`) intact. The identical failure pattern exists for MSE-free diffusion training, where the loss stays inside autocast because MSE is autocast-safe. |
| **T=200 confirmed by decision, not silently kept** | The brief prescribed T=1000; every starter file, both training notebooks and the evaluation helper hardcoded T=200 with the linear schedule. Keeping 200 preserves repo consistency, cuts sampling cost 5× on 4 GB VRAM, and still produced stable FID results; the trade-off (ᾱ_T = 0.132, so the forward chain never reaches pure noise) is documented rather than hidden. |
| **AMP everywhere during training, never during sampling** | `torch.amp.autocast("cuda")` + `GradScaler("cuda")` keep the UAV-scale models cheap on 4 GB (measured peaks: 0.47 GB diffusion training, 0.14 GB cGAN training). Sampling deliberately runs in fp32 with no autocast: 200 chained updates accumulate drift, and `empty_cache()` is called at the end of every sampling batch. |
| **OOM guard-rail: halve, retry once, then raise** | Both loops catch `torch.cuda.OutOfMemoryError`, call `torch.cuda.empty_cache()`, split the offending batch into two chunks with correctly offset labels, and raise a descriptive `RuntimeError` only if the split also fails. Gradient hygiene was audited: in every OOM path the failed step is either before `zero_grad()` or before `backward()`, so no partially-accumulated gradients leak into the retry. |
| **Checkpoint every epoch, plus an overwritten latest** | Each epoch writes `{cgan_generator, cgan_discriminator}_epoch_E.pt`, a combined `cgan_epoch_E.pt` (G+D states + optimizers + metrics) and overwrites `cgan_latest.pt`; diffusion writes `diffusion_epoch_E.pt` + `diffusion_latest.pt` and a final `diffusion_unet_epochfinal.pt` for the notebook's reload cell. Paths are `pathlib.Path` resolved from the module file, so nothing depends on the working directory. The result: **205 files / 6.28 GB** of reproducibility history. |
| **FID computed through one audited helper (`utils/metrics.py`)** | The helper converts [-1,1] grayscale to [0,1] RGB, feeds `FrechetInceptionDistance(normalize=True)` (which internally resizes 28×28 to the InceptionV3 input and casts to uint8), batches at 32 with `empty_cache()` between updates, and returns plain floats. Notebook 03 uses exactly this helper for both models, so the two FID numbers share one code path and one real subset (1000 images, deterministically selected). |
| **Downstream utility proven with a fixed classifier protocol** | The same `SimpleCNN` (32/64/128 convs + 128-FC head) is trained for 20 epochs on **only** each model's 1000 synthetic images and evaluated once on the real 10,000-image test set - one matched protocol, no per-model tuning, matching the rubric's "trained using ONLY synthetic data" requirement. |

## 3. Machine-Learning Principles in Practice

**The DDPM equations were implemented literally, not approximated.** The forward process uses the exact closed form `x_t = √ᾱ_t·x_0 + √(1-ᾱ_t)·ε` with `ᾱ` computed once as a cumulative product of the beta schedule before training; the reverse process reproduces the Ho et al. (2020) update with the fixed variance choice `σ_t = √β_t` and `z = 0` at `t = 0`. The final denoiser loss landed at 0.0424 (epoch mean), in the normal range for a 3.4M-parameter MNIST UNet at 50 epochs.

**GAN loss plateaus are equilibrium, not failure - and were verified, not assumed.** The cGAN's final-epoch losses (D 0.6858, G 0.7274) sit near the ln(2) adversarial equilibrium, which is expected for a small MLP cGAN without spectral norm. Rather than trusting the loss, an independent audit replayed a quick CNN trained on real MNIST over 1000 conditioned cGAN outputs: **88.7% of generated digits were classified as their conditioning label** with only ~83% real-set sanity accuracy - proof the conditioning survived the noisy D signal.

**Validation-style selection applies to generative models too - via a single fixed FID protocol.** Both FID numbers were computed against the *same* 1000-image real subset with the same helper, batch size and dtype handling, so the 69.92 vs 33.72 gap measures the models, not the harness. The boundary is stated in the notebook: FID at n=1000 is biased upward and these scores are meaningful as a relative comparison, not as absolute values comparable to published MNIST FIDs computed over 10k-50k samples.

**Synthetic-data utility must be trained on synthetic only.** The 89.9% / 91.3% downstream accuracies come from classifiers whose entire training signal is the generator's output (1000 images each, 100 per class); the real test set is touched once, at evaluation time. The instructive detail is the training losses: the cGAN-trained classifier fit to 0.0052 (memorizing a low-diversity distribution) while the diffusion-trained one stayed at 0.1056 (harder, more varied samples) - and the diffusion model still generalized better, which is exactly the diversity-versus-realism argument the rubric asks for.

**Mixed precision is a numerical contract, not a speed flag.** Every forward runs under `autocast`; every backward under `scaler.scale(...).backward()`; every step under `scaler.step()` + `scaler.update()`. The one place autocast is forbidden - BCE in the GAN - was restructured into an fp32 island rather than switching the discriminator to logits, because the architecture spec explicitly requires a final Sigmoid output.

**Reproducibility is part of the artifact.** All four notebooks set `SEED = 42` for `random`, `numpy`, `torch` and `torch.cuda.manual_seed_all` in a dedicated cell before any computation; the venv and kernel registration (`Python (udacity-dl-p4)`) are recorded, and every checkpoint in `checkpoints/` covers complete model + optimizer state per epoch.

**Claims stay inside the evidence.** All scores describe this pipeline's exact settings: MLP cGAN, 3.4M UNet, T=200, 50 epochs each, n=1000 FID sets, and CUDA-build torch 2.14.1 on a 4 GB Ada GPU. None are claimed to transfer to deeper architectures, cosine schedules, or T=1000 sampling.

## 4. AI Collaboration Playbook

The deliverable was four notebooks whose cells had to run in order, whose module code had to satisfy a TODO list, and whose printed numbers had to match the written analysis - so the workflow was built around **inspect → decide → repair → implement → smoke-test → wire → execute → verify**.

The workflow was:

1. **Read the entire repo before trusting the brief.** Plan-mode exploration of every source file and notebook found three discrepancies before any code was written: the brief's file map didn't match (`data_utils/` not `data/`; `utils/metrics.py` missing despite the README), several "TODO" items were already implemented in the starter (the UNet forward pass, the diffusion loop, the DDPM sampler), and `train_cgan.py`'s existing loop saved both G and D to the same overwritten path. The installed interpreters were also audited (Python 3.12 and 3.13 installs broken; 3.14 working).
2. **Surface ambiguity as explicit decisions.** Three conflicts (T=1000 vs T=200, cGAN architecture, execution depth) were presented to the human as decisions before implementing. All three were answered (T=200, spec architecture, full headless run), and every answer is traceable in the delivered artifacts.
3. **Repair the environment first.** cu121 wheels don't exist for Python 3.14, but the machine already carried `torch 2.14.1+cu132` with working CUDA, so the venv was built with `--system-site-packages` to reuse it; `torchmetrics[image]`, `torch-fidelity`, `jupyter` and `ipykernel` were installed into the venv; the `udacity-dl-p4` kernel was registered; CUDA was verified (`NVIDIA RTX 500 Ada Generation Laptop GPU`).
4. **Smoke-test before spending GPU hours.** A synthetic-batch script verified G/D output shapes, `torch.jit.script` exportability for both cGAN classes, UNet shape invariants, a 3-step reverse sampling, and one full epoch of each training loop against a fake 16-image dataset - all before the first real MNIST epoch, which is where the BCE/autocast incompatibility surfaced and was fixed for pennies instead of after a 50-epoch run.
5. **Wire the notebooks programmatically.** Cells marked by existing cell IDs were filled/replaced via a JSON-manipulation script, so every pre-existing markdown and already-written cell stayed byte-identical; seeds were inserted at the top of all four notebooks and the kernelspec was switched to `udacity-dl-p4`.
6. **Execute, then verify with real numbers.** Notebooks 00 and 01 ran first (00 confirmed device/counts; 01 after 50 epochs printed 205 checkpoint artifacts including `cgan_latest.pt`). Notebook 02 ran in the background (~45 minutes, 938 batches/epoch peaking at 17.58 it/s, final loss 0.0424). Notebook 03 downloaded the Inception weights and printed both FIDs and both downstream accuracies.
7. **Independent review pass.** A separate review read every file, re-derived the math, audited the OOM fallback for gradient leakage, measured VRAM peaks with `max_memory_allocated()`, confirmed the 88.7% label fidelity, and computed `ᾱ_T = 0.132` for the chosen schedule - rating the project PASS WITH MINOR FIXES, with the minors documented as conscious keeps (Section 7).

The collaboration principle from P2 carries over unchanged: **verify, don't trust.** Every figure in these notes was read from an executed notebook, a checkpoint file, or a measured probe - and the brief's assumptions (file names, "missing" code, T=1000) were treated as hypotheses to check, not facts to build on.

## 5. Evaluation & Verification Philosophy

**Executed outputs are the evidence.** The dataset counts (60,000 train / 10,000 test with the correct class skew), the parameter counts (1,498,448 / 2,263,051 / 3,414,209), the per-epoch checkpoints, the FID values (69.92 / 33.72), the downstream accuracies (89.9% / 91.3%) and the diffusion speed (17.58 it/s) were all extracted from the executed notebooks or recomputed from the delivered modules - not recalled or estimated.

**Correctness was checked by contract, not by eye.** A smoke script pinned the public contracts: G emits `(B,1,28,28)` with Tanh-bounded values; D emits `(B,1)` probabilities from a `(B,2,28,28)` input; the UNet returns noise predictions with the exact input shape; both `Generator` and `Discriminator` survive `torch.jit.script`; `sample_images` returns clamped [-1,1] tensors with labels aligned.

**The environment audit ran until it found real numbers.** `python -V` 3.14.7; `Python312/` containing only `Doc`; no `py` launcher; `pip index versions torch --index-url .../cu121` → "No matching distribution found"; the cu128/cu130 indexes listing cp314 wheels; `torch.cuda.is_available() → True` with device name from the venv. Each fact is a printed probe, and the venv decision cites them.

**Sampling quality was inspected visually and statistically.** The 100-sample diffusion grid (10 per class), the cGAN grid, and the final 3×10 real-vs-cGAN-vs-diffusion comparison were rendered and inspected; the label-fidelity metric (88.7%) gives the visual judgment a number. The diffusion row's occasional degraded sample (e.g. a blurry "8") is visible in the grid and acknowledged in the conclusions rather than hidden.

**VRAM was measured, not assumed.** Peak allocations were captured with `torch.cuda.max_memory_allocated()` on the delivered step implementations: **0.47 GB** (diffusion train step, batch 64, AMP), **0.25 GB** (100-image sampling batch, 200 steps, fp32), **0.14 GB** (cGAN train step, batch 128, AMP) - an order of magnitude inside the 4,094 MiB budget, which is why the OOM guard-rail never had to fire.

**Notebook hygiene is binary.** All four notebooks validate with `nbformat`, contain **zero TODO markers**, and carry the `udacity-dl-p4` kernelspec; the checkpoint directory exists with all required artifacts; `torch.cuda.empty_cache()` is called after every epoch in both training loops, in every sampling batch, and inside the FID helper.

## 6. Challenges & Resolutions

### Challenge 1 - Python 3.14 is the machine's only working interpreter and cu121 wheels do not exist for it

**What happened:** The brief prescribed `python -m venv .venv` with a CUDA 12.1 install. The machine's reality: the system `python` is 3.14.7; `Python312/` contains only a `Doc` folder and `Python313/` ships no `python.exe`; the `py` launcher is absent. And `pip index versions torch --index-url https://download.pytorch.org/whl/cu121` returned "No matching distribution found" - the cu121 index stops at cp312.

**Resolution:** Discovered the global Python 3.14 already carried `torch 2.14.1+cu132` / `torchvision 0.29.1+cu132` with working CUDA on the RTX 500 Ada. Built the venv with `--system-site-packages` so it reuses that CUDA build, installed the remaining requirements (matplotlib, tqdm, torchmetrics[image], torch-fidelity, jupyter, ipykernel) into the venv, registered the `udacity-dl-p4` kernel, and re-verified `torch.cuda.is_available()` inside the venv. The brief's cu121/fresh-venv plan was recorded as a documented environment deviation, not silently substituted.

### Challenge 2 - BCELoss is unsafe under autocast

**What happened:** The first smoke test of the AMP training loop crashed immediately: `RuntimeError: torch.nn.functional.binary_cross_entropy and torch.nn.BCELoss are unsafe to autocast`. PyTorch refuses BCE inside an autocast region because a Sigmoid→BCE stack loses its fp32 stability guarantee.

**Resolution:** Kept the architecture (Sigmoid output is a spec requirement) and moved the loss, not the model: GAN forwards stay under `autocast`, predictions are `.float()`-cast, and both BCE losses are computed in fp32 outside the autocast block, then fed through the shared `GradScaler` (`scale → backward → step → update`). The diffusion loop keeps its MSE inside autocast, where MSE is autocast-safe. The corrected smoke test then exercised both loops end-to-end.

### Challenge 3 - The brief described a repo state that largely did not exist

**What happened:** Three mismatched assumptions: (a) `utils/metrics.py` was listed in the README and in the brief as "already implemented" - it did not exist; (b) `model/diffusion.py`'s forward pass and both diffusion functions were described as TODOs - they were already implemented in the starter, correctly except for a hacky `timestep_embedding(t, t.shape[0] * 0 + 128)`; (c) `train_cgan.py`'s "TODOs to complete" were already filled with a working loop - but trained G before D with no fresh D for the G step, and saved both G and D states to the same overwritten nonsense path `../pytorch-docker-env/checkpoints10.pt` every 10 epochs. Grep for `TODO` across the whole repo returned zero matches.

**Resolution:** Accepted all genuinely working starter code (the UNet, the diffusion loop and sampler's math, the sampler's signature the notebooks already call), rewrote the cGAN model classes to the brief's architecture, reworked the training loop to D-then-G with proper per-epoch checkpointing (pathlib-resolved `Path(__file__)` parents so paths survive any CWD), created `utils/metrics.py` from scratch, and replaced the time-dimension hack with a stored `self.time_dim` attribute.

### Challenge 4 - The brief's T=1000 conflicted with T=200 hardcoded across the starter

**What happened:** The brief prescribed 1000 diffusion timesteps. The starter's `train_diffusion` defaults, `sample_images`, both training notebooks and notebook 03's evaluation helper all hardcoded T=200 with the linear β schedule (1e-4 → 0.02) - changing it would touch existing, non-TODO cells and slow sampling 5×, while keeping it contradicts the brief.

**Resolution:** Presented as an explicit user decision with the trade-offs spelled out; the decision was **T=200**. A documented consequence from the later review was quantified numerically: with this schedule, `ᾱ_T = 0.132` (√ᾱ_T ≈ 0.36), so the forward chain never reaches pure noise where the paper's T=1000 setup does (ᾱ_T ≈ 4e-5) - noted as a known limitation that caps sample quality slightly rather than retraining, since the executed results already cleared every rubric requirement.

### Challenge 5 - Notebook 03 shipped with latent bugs that would have produced meaningless metrics

**What happened:** Four issues in the starter notebook: (a) `from src.training.train_diffusion import linear_beta_schedule` inside a helper function - a guaranteed `ModuleNotFoundError` (there is no `src/` package); (b) the FID comparison and the downstream classifiers ran on **10 generated images total** - FID over 10 real vs 10 fake images is statistical noise, and a CNN trained on 10 images proves nothing about utility; (c) real sampling for the helper's classes iterated `range(len(mnist))` per class; (d) an instantiating-but-never-used FID object cell.

**Resolution:** Fixed the import path; parameterized generation with `n_per_class` and generated **100 per class (1000 per model)** for FID, the comparison grid and the classifiers, grouped per class (one class per batch) to respect the VRAM budget; rewrote real-sample extraction on `targets` indices so the 1000-image real subset builds in seconds; rerouted the FID calls through the new `utils/metrics.fid_score` so both models share one implementation. The two starter cells left untouched by review decision (regeneration cell and the global min-max normalize) are documented as conscious keeps - the latter is near-identity for outputs already in [-1,1].

### Challenge 6 - The 100-image grids printed unreadable titles

**What happened:** `show_batch` used a fixed `figsize=(6,6)`, so a 10×10 grid of the required "10 samples per class" rendered titles as an overlapping "Label: 0Label: 0..." strip - legible neither as a rubric artifact nor for visual QC.

**Resolution:** `show_batch` now scales the figure with the grid size and shrinks title fonts for large grids. Notebook 01 was re-executed end-to-end (50 epochs retrained, checkpoints regenerated under the same seed); notebook 02's final figure was regenerated from the trained checkpoint and re-injected into the saved notebook so the delivered artifact shows the readable grid without paying for a second 45-minute diffusion training.

## 7. Review & Refinement

The principal refinement was **replacing the starter's cGAN training loop with the spec's loop after reading it carefully**. The starter trained the Generator first and saved both models' states to a single overwritten path - i.e. the "checkpoints" were unusable. The delivered loop trains D first (real+fake losses averaged), then G through a fresh D, and writes five distinct artifacts per epoch; `cgan_latest.pt` now contains full resumable state (G+D weights, both optimizers, epoch, losses).

A second refinement was **getting AMP right for a Sigmoid+ BCE discriminator architecture**. The naive `autocast`-wrapped loop fails at runtime; the delivered structure interleaves autocast forward blocks with fp32 loss islands, which is the only way to keep both the speed benefit and the spec's Sigmoid output.

A third refinement was **the figures a human actually reads**. ## 10. Retrospective

### What I'd Do Differently

1. **Add a cosine or rescaled-β schedule next to the linear one.** The review pass quantified the cost of keeping T=200 with the paper's β_end: `ᾱ_T = 0.132`, so the terminal timestep is under-noised. A `β_end ≈ 0.05` linear schedule or a cosine schedule would push `ᾱ_T` to pure-noise territory and likely shave a few FID points; the rubric even lists schedule comparison as a standout item.
2. **Save the FID/classifier evaluations to disk, not just stdout.** The metrics live in notebook outputs; a small JSON artifact in `checkpoints/` (model → FID/accuracy) would let later runs diff against earlier ones without re-executing notebook 03.
3. **Deduplicate the evaluation generation.** Notebook 03 regenerates both synthetic sets after the FID stage (a pre-existing cell kept by decision); dropping that duplication would more than halve notebook 03's runtime with zero analytical change.
4. **Resume checkpoints should be self-loading by the project's own helper.** `cgan_latest.pt` stores richer state than the starter `load_checkpoint` expects; a one-line compatibility key would make the "easy resumption" artifact actually consumable by `load_checkpoint` today.
5. **Sample-evaluate FID on a larger real set before claiming absolute numbers.** n=1000 keeps the run cheap on 4 GB; n=10k would drop the estimator bias and make the FIDs quotable against published comparisons, at ~10× the Inception forward cost.

### What Worked Well

1. **Reading the starter before writing.** Knowing exactly which pieces were already correct (UNet, DDPM math, sampler signature) meant the delivered code keeps those parts untouched and concentrates changes where the bugs actually were.
2. **Smoke tests before long runs.** The synthetic AMP loop exposed the BCE/autocast incompatibility in seconds, before any 50-epoch investment; `torch.jit.script` checks ran before checkpoints were ever saved.
3. **Decisions surfaced as questions, not silent choices.** T vs T=200, architecture, and execution depth were put to the human up front; the delivered artifacts record each answer and its rationale.
4. **Diagnosis with a metric, not a squint.** The 88.7% conditioning audit turned "the digits look right" into a number, and `max_memory_allocated()` turned "it should fit in 4 GB" into 0.47 GB.
5. **A rubric-driven review pass.** The independent review re-derived the math, audited the guard-rail's failure paths, and measured `ᾱ_T` numerically - catching the under-diffusion issue and the key-naming mismatch for documentation even though no deliverable was blocked.

### The AI Partnership

> "The value of the AI partnership here was resolving a three-way conflict between a brief, a starter and a machine - and preferring evidence over any of them. The planning pass read the whole repo and found that the brief's file map, TODO claims and T=1000 prescription were all wrong for this codebase and environment; the startup work then pinned the environment (Python 3.14-only, cu121 unavailable, CUDA torch available globally) instead of following the prescribed commands into failure. When the first AMP smoke test crashed on BCE, the fix was made on a 16-image loop rather than a 50-epoch run. The human's role was judgment on three explicit trade-offs - timestep count, architecture, and execution depth - and later, sealing the review's minor issues as documented keeps so the notebooks remained the delivered artifact. Every figure in these notes was read from an executed cell, a checkpoint, or a measured probe; nothing is recalled, and the one architectural limitation that remains (ᾱ_T = 0.132 at T=200) is quantified rather than hidden."

### Final Thoughts

This project was less about generating pretty digits and more about making two different generative paradigms work under identical, audited conditions: same data loader, same seeds, same VRAM budget, same evaluation harness, same real subset. The cGAN's high downstream accuracy (89.9%) despite a mediocre FID shows that usefulness and realism are different axes; the diffusion model's double win (33.72 FID, 91.3% utility) at 200× the sampling cost shows where the quality ceiling is. Both trainings ran inside 0.5 GB of a 4 GB card with zero OOMs, both checkpoints cover full optimizer state per epoch, and the one compromise made for budget and consistency (T=200) is stated in the artifacts with its measured consequence. The final artifact is reproducible, rubric-mapped end to end, and documented with numbers taken from its own execution.
